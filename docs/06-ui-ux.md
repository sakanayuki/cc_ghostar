## 6.1 UX フロー

原典 §21 のフローを、[Q16 の決定](./09-design-md-mapping.md#92-主要な設計判断)に基づくリトライ導線まで含めて定義する。

```text
  ページ読み込み
        │
        ▼
  capability 検出（カメラ有無 / WebGL / センサー）
        │
        ├─ WebGL 不可 ──────→ 起動不可画面（終端）
        ├─ センサー不可 ────→ 起動不可画面（?mock=1 なら続行）
        │
        ▼
  ┌─ タイトル画面 ─────────────────────────┐
  │   TORCH WEBAR HORROR                   │
  │   遊び方の説明（3 行）                   │
  │   注意書き（音量・驚かせ演出）            │
  │   最短クリア記録                         │
  │   ［ 探索を開始する ］                   │
  └────────────────┬───────────────────────┘
                   │ タップ（= ユーザー操作。以降の API 呼び出しの起点）
                   │
                   ├─ 全画面 / 向きロック / Wake Lock
                   ├─ AudioContext 解錠
                   │
       ┌───────────┴──── 初回のみ ────┐
       ▼                              │
  カメラ許可要求                       │
       │                              │
       ├─ 拒否 ──→ エラー画面（再試行）  │
       │                              │
       ▼                              │
  Torch capability 検査               │
       │  （非対応なら一度だけ告知）      │
       ▼                              │
  センサー購読開始                     │
       │                              │
       └──────────┬───────────────────┘
                  ▼
  ┌─ キャリブレーション画面 ────────────┐
  │   端末を正面に構えてください          │
  │   ［ この向きを正面にする ］          │
  └────────────────┬────────────────────┘
                   ▼
              プレイ中
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
   全 3 体を浄化            捕まる
       │                       │
       └───────────┬───────────┘
                   ▼（演出 1.4 秒）
  ┌─ 結果画面 ──────────────────────────┐
  │   CLEARED / CAUGHT                  │
  │   経過時間・浄化数・記録更新表示       │
  │   ［ もう一度 ］                     │
  └────────────────┬────────────────────┘
                   │
                   └──→ タイトル画面へ戻る
                        （カメラ・センサー・全画面は保持）
```

### ユーザー操作を起点とする API

原典 §21 の「Permission 要求はユーザー操作をトリガーとして実行する」を守るため、
以下はすべて**タイトル画面の START タップのハンドラ内**から呼ぶ。

| API | 理由 |
| --- | --- |
| `getUserMedia` | 許可プロンプトの表示にユーザー操作が必要 |
| `requestFullscreen` | ユーザー操作必須 |
| `screen.orientation.lock` | 全画面が前提、かつユーザー操作必須 |
| `AudioContext.resume` | モバイルの自動再生制限 |
| `navigator.vibrate`（初回） | ユーザー操作前の振動はブロックされる |

`await` を挟んだ後に呼ぶと操作との関連が切れる端末があるため、
**同期的に呼び出しを開始し、結果を後で待つ**構造にすること。

```typescript
// 良い例：すべての呼び出しを同期的に開始する
const fullscreenP = document.documentElement.requestFullscreen();
const audioP = audioCtx.resume();
const cameraP = navigator.mediaDevices.getUserMedia(CONSTRAINTS);
await Promise.allSettled([fullscreenP, audioP, cameraP]);
```

## 6.2 画面の向きと没入モード

[Q10 の決定](./09-design-md-mapping.md#92-主要な設計判断)により縦持ち固定とする。

向きロックに失敗した端末で横持ちにされた場合、**ゲームは止めずに**オーバーレイで回転を促す。

```text
┌──────────────────────────────┐
│                              │
│         ⟲                    │
│   端末を縦向きにしてください    │
│                              │
└──────────────────────────────┘
```

```css
@media (orientation: landscape) {
  #rotate-overlay { display: flex; }
}
```

ゲームループは動き続け、ゴーストも接近し続ける。
オーバーレイで隠して安全にする（＝ポーズする）と、
「横持ちにすれば時間が止まる」という抜け道になるため。

## 6.3 画面レイヤ

```text
┌─────────────────────────────────────┐
│ z-index 4 : オーバーレイ              │  エラー / 回転促し / 告知
├─────────────────────────────────────┤
│ z-index 3 : 画面効果                  │  暗転 / ビネット / ノイズ
├─────────────────────────────────────┤
│ z-index 2 : HUD                      │  照準 / ボタン / 残数
├─────────────────────────────────────┤
│ z-index 1 : Three.js canvas          │  ゴースト（透過）
├─────────────────────────────────────┤
│ z-index 0 : video                    │  カメラ映像
└─────────────────────────────────────┘
```

HUD はすべて DOM で構成する。Three.js 内に UI を描画しない。
DOM の方が文字のレンダリング品質が高く、レイアウトの調整も容易であり、
何より**描画負荷がフレーム予算を食わない**。

## 6.4 HUD の構成

原典 §23 が要求する 3 つのボタン（Torch / Calibration / Debug）に、
ゲーム進行の表示を加える。

```text
┌─────────────────────────────────────┐
│  残り 3      00:24        ⚙          │ ← 上段：状態表示
│                                     │
│                                     │
│                                     │
│              ╭───╮                  │ ← 中央：照準
│              │   │                  │   光錐の範囲を示す円
│              ╰───╯                  │
│           ▓▓▓▓▓░░░░░                │ ← 照準直下：浄化ゲージ
│                                     │
│                                     │
│                                     │
│                                     │
│   ［ 正面を再設定 ］   ［ 💡 ］        │ ← 下段：操作
└─────────────────────────────────────┘
```

### 照準

画面中央に、**光錐の半頂角に対応する大きさの円**を描く。

この円は装飾ではなく、[03.5](./03-domain-model.md#光錐の角度と描画-fov-の関係) で定めた
「光錐（20°）は視野（60°）より狭い」という設計をプレイヤーに伝える唯一の手段である。
円の半径は FOV と光錐角から幾何的に算出する。

```typescript
// 画面中心から、半頂角 beamHalfAngle に対応するピクセル距離
const radiusPx =
  (Math.tan(config.beamHalfAngle) / Math.tan(MathUtils.degToRad(fovDeg / 2)))
  * (window.innerHeight / 2);
```

| 状態 | 表示 |
| --- | --- |
| 何も捕捉していない | 細い白の輪郭、不透明度 0.3 |
| 捕捉中 | 輪郭が明るくなり、わずかに拡大 |
| 照射 OFF | 輪郭が破線になる |

### 残数表示

画面左上の「残り N」は**セッションの残り総数**（`ghostCount - purifiedCount`）である。
同時に存在するのは 1 体だけなので、画面内の生存数を出しても常に 1 にしかならず意味がない。

### 浄化ゲージ

捕捉中のゴーストがあるときのみ、照準の直下に表示する。
同時に存在するのは 1 体だけなので、常に 1 本でよい。

減衰中（捕捉が外れた直後）はゲージの色を変え、
「まだ残っているが減っている」ことを示す。これにより
`purifyDecayPerSec` が緩やかであること（[04.4](./04-game-rules.md#44-チューニング値gameconfig)）が
プレイヤーに伝わり、一瞬視線を外すことを許容できると理解される。

### 接近の警告

画面端に、**ゴーストのいる方向を示すインジケータ**を出す。

| 距離 | 表示 |
| --- | --- |
| `visibleMaxDistance` 以上 | 表示しない |
| 接近中 | 画面端に薄い赤のグラデーション。方向に対応する辺に出る |
| `hapticWarnDistance` 以下 | グラデーションが強まり、脈打つ（周期 1.2 秒 = 0.83Hz） |

脈動の周期は [6.6](#66-安全上の制約) の制約を満たす範囲に収める。

> この視覚インジケータは空間音響（[05.5](./05-infrastructure.md#55-audioport-の実装)）の
> **補助**であり、代替ではない。イヤホンなしのスピーカー再生では定位が弱くなるため、
> 視覚的な手がかりを併置する。ただし方向の精度は音より粗く（4 方向程度）、
> 音で探す体験を置き換えないようにする。

### 操作ボタン

| ボタン | 動作 |
| --- | --- |
| 正面を再設定 | 再キャリブレーション（[03.4](./03-domain-model.md#再キャリブレーション)） |
| 💡（照射） | `LightState` のトグル。Torch 非対応時もボタンは有効 |
| ⚙（デバッグ） | デバッグ HUD の表示切替。`?debug=1` 指定時のみ表示 |

タップ領域は最小 48×48 px を確保する。
暗所で片手持ちのまま操作されることを前提に、画面下端の親指が届く範囲に配置する。

## 6.5 デバッグ HUD

原典 §24 の表示項目を実装する。
[Q15 の決定](./09-design-md-mapping.md#92-主要な設計判断)により `?debug=1` で有効化し、
**本番バンドルに含める**。

```text
┌─ DEBUG ─────────────────────────────┐
│ FPS        58  (min 41)             │
│ frame      16.8ms                   │
│                                     │
│ camera     active  1280x720         │
│ torch      AVAILABLE / ON           │
│ light      ON                       │
│ sensor     absolute  (mock: off)    │
│                                     │
│ orient     α 142.3  β 78.1  γ -2.4  │
│ screen     0°                       │
│ camQuat    (0.02, 0.71, -0.01, 0.70)│
│ yaw        +38.2°                   │
│ calib      +104.1°                  │
│                                     │
│ accel      2.1  (peak 24.6)         │
│ shake      ready                    │
│                                     │
│ ghosts     3 alive                  │
│  #0  az +122°  d 4.21  APPROACHING  │
│      purify 0.00  esc 0  vis 0.00   │
│  #1  az  -18°  d 2.84  HELD         │
│      purify 0.62  esc 1  vis 0.94   │
│  #2  az +241°  d 7.03  APPROACHING  │
│      purify 0.00  esc 0  vis 0.00   │
│                                     │
│ audio      running  ctx 48000Hz     │
│ elapsed    00:31.4                  │
└─────────────────────────────────────┘
```

### 表示項目と用途

| 項目 | 何の調整に使うか |
| --- | --- |
| FPS / 最小 FPS / フレーム時間 | 原典 §27 の性能目標の達成確認 |
| camera / torch / light / sensor | capability 検出の正しさ。特に `torch` と `light` が**独立に**動くことの確認 |
| orient / screen / camQuat / yaw | 姿勢変換のデバッグ。横持ち時の `screen` 補正の検証 |
| calib | キャリブレーションが効いているか |
| accel / peak | [05.4](./05-infrastructure.md#54-motionport-の実装) のシェイク閾値の調整 |
| wave / nextSpawn | 逐次出現の進行と補充待ち時間。何体目かと残りが一目で分かる |
| ghosts 各行 | `GhostBehavior` の遷移の追跡。`vis` は `computeOpacity` の出力 |
| audio | `AudioContext` の解錠確認 |

### 実装方針

- DOM の更新は **4 フレームに 1 回**に間引く。毎フレーム更新すると計測対象を歪める
- 文字列連結ではなく、行ごとに `textContent` を更新する
- `?debug=1` がない場合、HUD の DOM を生成しない（存在しないものは重くならない）

### 起動オプション

```typescript
// shared/RuntimeOptions.ts
export interface RuntimeOptions {
  debug: boolean;     // ?debug=1  デバッグ HUD
  mock: boolean;      // ?mock=1   センサー・カメラをモックに
  noTorch: boolean;   // ?notorch=1 Torch 非対応端末を擬似再現
  mute: boolean;      // ?mute=1   音を止める
  ghosts?: number;    // ?ghosts=5 ゴースト数の上書き
  speed?: number;     // ?speed=0.5 接近速度の上書き
}
```

`?notorch=1` は、Torch 対応端末で**非対応端末の挙動を再現する**ためのもの。
[Q8 の決定](./09-design-md-mapping.md#92-主要な設計判断)で分離した `LightState` が
本当に独立して動くかを、対応端末 1 台で検証できる。

`?ghosts` / `?speed` は `GameConfig` の上書きであり、
実機でバランスを試す際にビルドし直さずに済む。

## 6.6 安全上の制約

[Q17 の決定](./09-design-md-mapping.md#92-主要な設計判断)による。
**これらは演出上の好みではなく、守るべき制約として扱う。**

### 明滅の禁止

| 対象 | 制約 |
| --- | --- |
| 物理 Torch（LED） | **点滅演出を一切実装しない。** 状態変化としての ON/OFF のみ |
| 画面全体の輝度変化 | **3Hz を超える周期的変化を禁止する** |
| 画面の局所的な点滅 | 同上。警告インジケータの脈動は 0.83Hz とする |
| 全白フラッシュ | **使用しない** |

光過敏性発作の誘発リスクを避けるためである。
現実の LED を制御できるアプリケーションである以上、この配慮は通常の Web ページより重い意味を持つ。

加えて、暗所で顔の至近にある画面が突然全白になる演出は、
発作リスクとは別に単純に目への負担が大きい。

### 驚かせ演出の設計

`GAME_OVER` の演出は次の構成とする。

```text
接触の瞬間
  ├─ ゴーストが画面を覆うまで 0.25 秒で拡大（急だが瞬間的ではない）
  ├─ 短い悲鳴（0.4 秒、ピーク音量は通常の 1.4 倍まで）
  ├─ 振動 200ms
  └─ 0.35 秒かけて暗転
        ↓
     結果画面（1.4 秒後）
```

音量のピークを 1.4 倍に抑える。
イヤホン使用時に不快・有害な音量になることを避けるため、
`masterGain` に対してリミッター（`DynamicsCompressorNode`）を常時挿入する。

```typescript
const limiter = ctx.createDynamicsCompressor();
limiter.threshold.value = -6;
limiter.ratio.value = 12;
limiter.attack.value = 0.003;
masterGain.connect(limiter).connect(ctx.destination);
```

### モーション軽減への対応

```css
@media (prefers-reduced-motion: reduce) {
  /* 画面の揺れ・ノイズを無効化する */
}
```

`prefers-reduced-motion: reduce` が有効な場合、次を抑制する。

- 画面の揺れ（シェイクエフェクト）
- ノイズオーバーレイ
- `GAME_OVER` 時の拡大演出（暗転のみに簡略化）

ゲームルール自体は変更しない。恐怖表現の強度のみを下げる。

### 事前の告知

タイトル画面に、プレイ前の注意書きを常時表示する。

```text
・音が出ます。音量にご注意ください
・暗い場所での使用を想定しています。周囲の安全を確認してください
・驚かせる演出が含まれます
```

3 番目は、ホラー体験であることを知らずに他人へ端末を手渡されるケースへの配慮である。

2 番目は本作固有の実際的なリスクである。
プレイヤーは画面を見ながら暗所で体を回転させるため、
**家具への衝突や転倒の危険がある**。ゲームデザイン上プレイヤーは移動しないが、
回転はする。この告知は省略しない。

## 6.7 文言

原典 §25 の文言を基礎とする。すべて日本語固定（[01.4](./01-overview.md#14-スコープ)）。

### エラー・告知

| 場面 | 文言 |
| --- | --- |
| カメラ拒否 | `カメラへのアクセスが必要です。`<br>`ブラウザの設定から許可してください。` |
| カメラ占有 | `カメラを使用できません。`<br>`他のアプリを終了してから再試行してください。` |
| Torch 非対応 | `この端末ではライト制御に対応していません。`<br>`画面内のライトだけで探索します。` |
| センサー不可 | `端末の方向センサーを利用できません。` |
| WebGL 不可 | `お使いのブラウザでは動作しません。`<br>`Android の Chrome でお試しください。` |
| 横持ち | `端末を縦向きにしてください` |

Torch 非対応の文言は、**ゲームが問題なく遊べることを明示する**。
原典 §25 の文言だけでは「遊べないのではないか」と受け取られる可能性があるため、
2 行目を追加した。これは [Q8 の決定](./09-design-md-mapping.md#92-主要な設計判断)の帰結である。

### ゲーム内

| 場面 | 文言 |
| --- | --- |
| キャリブレーション | `端末を正面に構えて、ボタンを押してください` |
| プレイ開始 | `光を当てて、視界から消してください` |
| 掴みかかり | `振り払え！` |
| 振り払い成功 | `——今のうちに` |
| 浄化完了 | `浄化した` |
| クリア | `CLEARED` |
| 敗北 | `CAUGHT` |
| 記録更新 | `自己最短記録` |

## 6.8 スタイル方針

- 配色は暗所を前提とする。背景は透過、文字は白〜薄青（`#dde8f0`）
- **純白（`#ffffff`）の大面積を使わない。** 暗順応した目には眩しすぎる
- 文字には必ず影またはアウトラインを付ける。カメラ映像の上では明るい被写体に重なると読めなくなる
- フォントはシステムフォント（`system-ui`）。Web フォントを読み込まない（初期表示を遅らせないため）
- HUD の不透明度は控えめにし、カメラ映像を覆い隠さない

```css
:root {
  --fg: #dde8f0;
  --fg-dim: rgba(221, 232, 240, 0.55);
  --danger: #c8412f;
  --accent: #7fd4ff;
}

.hud-text {
  color: var(--fg);
  text-shadow: 0 1px 3px rgba(0, 0, 0, 0.9);
}
```

ダークモード・ライトモードの切り替えは実装しない。
本作は常に暗所前提の単一配色で動作する。
